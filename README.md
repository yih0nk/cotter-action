# cotter-action

**Run [Cotter](https://github.com/yih0nk/cotter) — "pytest for robot
policies" — in CI, gate the build on the result, and post a sticky report
comment on the pull request.**

Cotter loads a trained robot policy as a black box and runs it through a
standardized battery — **performance** (Wald SPRT), **safety** (per-timestep
hard limits), **regression** (matched-pairs McNemar / Wilcoxon), and
**adversarial** (a PPO attacker that perturbs observations within an L∞
budget). This action wires that battery into GitHub Actions so every retrain
is checked automatically, the way `pytest` checks every commit.

---

## Quickstart

Add `.github/workflows/cotter.yml` to your policy repo:

```yaml
name: cotter
on:
  pull_request:
permissions:
  contents: read
  pull-requests: write        # required for the PR comment
jobs:
  cotter:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: yih0nk/cotter-action@v1
        with:
          policy: checkpoints/grasp_v3.zip
          config: cotter.yaml
```

`config` is a standard Cotter YAML config (see the
[Cotter README](https://github.com/yih0nk/cotter#quickstart-cli)). On every
pull request the action runs the battery, fails the check if a category
fails, and leaves a comment like this:

---

## Cotter report

**Policy** `grasp_v3` on `FetchPickAndPlace-v4` — OVERALL: ❌ **FAIL**

`3` passing · `1` failing · `0` informational

| | Category | Test | Result |
|:--:|---|---|---|
| ✅ | `performance` | `sprt_success_rate` | PASS: 47/50 successes (94.0%, 95% CI [83.5%, 98.7%]) |
| ✅ | `safety` | `hard_limits` | PASS: no violations in 20020 timesteps across 20 trials |
| ✅ | `regression` | `success_mcnemar` | NO_REGRESSION: baseline 0.92 vs candidate 0.94 over 30 paired trials |
| ❌ | `adversarial` | `learned_ppo` | FAIL: 94.0% clean → 0.0% under ppo linf perturbation (eps=0.07, required ≥ 50%) |

<sub>🛡️ Generated by cotter-action · report schema v1 · workflow run</sub>

---

## What it does

1. Installs `cotterbot` from PyPI (pin with `cotter-version`).
2. Runs `cotter run` (full battery) or `cotter compare` (regression only).
3. Writes the report to the **job summary** and, on pull requests, a
   **sticky PR comment** (updated in place on re-runs, not duplicated).
4. Uploads the **JSON** report — and the **HTML** report, when the installed
   `cotterbot` produces one — as a workflow artifact.
5. **Fails the step** if a category failed or a regression was detected
   (toggle with `fail-on-error`).

## Modes

| Mode | Command | Use it for |
|---|---|---|
| `run` (default) | `cotter run` | The full battery on a single policy. |
| `compare` | `cotter compare` | "Did my retrain regress?" — the paired regression test between a `baseline` and the candidate `policy`. Fast enough for every PR. |

See [`examples/`](examples/) for copy-paste workflows: a PR gate, a
regression-on-retrain check, and a nightly full battery.

## Inputs

| Input | Default | Description |
|---|---|---|
| `policy` | — (required) | Policy under test (SB3 `.zip` or torch `.pt`). In `compare` mode, the candidate. |
| `config` | — (required) | Cotter YAML config declaring the test battery. |
| `command` | `run` | `run` (full battery) or `compare` (regression only). |
| `baseline` | `""` | Baseline policy for `compare` mode. |
| `env` | `""` | Gymnasium env id override (defaults to the config's `env`). |
| `cotter-version` | `""` | `cotterbot` version to install (e.g. `0.1.0`). Empty = latest. |
| `python-version` | `3.11` | Python version. |
| `title` | `Cotter report` | Heading in the summary and comment. |
| `comment` | `true` | Post/update a sticky PR comment (pull_request events only). |
| `comment-tag` | `default` | Identifier for the sticky comment, so multiple Cotter jobs each own one. |
| `upload-artifact` | `true` | Upload the JSON (+ HTML) report as a workflow artifact. |
| `report-name` | `cotter-report` | Name of the uploaded artifact. |
| `fail-on-error` | `true` | Fail the step on a category failure / regression. |
| `working-directory` | `.` | Directory to resolve `policy`/`config` against. |
| `github-token` | `${{ github.token }}` | Token for the PR comment (needs `pull-requests: write`). |

## Outputs

| Output | Description |
|---|---|
| `outcome` | `pass` or `fail`. |
| `report-json` | Path to the JSON report (empty if none was produced). |
| `report-html` | Path to the HTML report (empty if the installed `cotterbot` did not produce one). |

## Permissions

The sticky PR comment needs write access to pull requests:

```yaml
permissions:
  contents: read
  pull-requests: write
```

Without it, the action still runs and gates the build — it just logs that it
could not comment. On forked-PR events the default token is read-only; use
`pull_request_target` (carefully) or skip commenting there.

## cotterbot compatibility

The action reads Cotter's **versioned JSON report schema**, not its Python
API, and **feature-detects** the optional `--report` / `--report-html` flags
from `--help`. So it works across `cotter` versions: older ones simply skip
the artifacts they cannot produce (e.g. the HTML report predates some
published builds). The Markdown comment and the pass/fail gate always work.

## Versioning

Pin to the major tag so you get fixes without breaking changes:

```yaml
uses: yih0nk/cotter-action@v1
```

Or pin to an exact release (`@v0.1.0`) or commit SHA for full reproducibility.

## How it works

A composite action, no Docker image to pull:

```
action.yml                 inputs/outputs + steps (install → run → publish → upload → gate)
scripts/run.sh             runs cotter, feature-detects flags, normalizes 0/1/2 → outcome
scripts/report_markdown.py pure JSON-report → Markdown renderer (unit-tested)
scripts/post.py            writes the job summary + upserts the sticky PR comment (stdlib only)
```

## Development

